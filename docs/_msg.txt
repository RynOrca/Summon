Bind a summoned session to its project folder, and stop showing raw tool JSON

Three things the user hit in Agent mode.

1. Picking a project folder did nothing. project/set only changes the host's
   active project; a session's working directory comes from its own projectPath.
   session/create has accepted projectPath all along (pi_session_create) and the
   plugin never sent it, so new sessions landed in the default project. It is now
   sent on create, session/moveProject moves an existing (idle) session, and a
   chip at the bottom-left of the composer always shows which project this
   session is actually bound to - read from session/get, so it reports the host's
   truth rather than the local intention. The choice is remembered.

2. The tool row showed the result's raw JSON truncated mid-object, which is what
   the screenshot was pointing at. The title is now built from the structured
   fields worth reading (exit code, +/- lines, count, bytes, path), with concrete
   values deliberately ahead of the generic {ok:true}, and the raw output moved
   into a collapsed <pre>.

3. The host draws its "top 46px is drag-only" development hint for
   development-loaded panels in the v2 safe-area chrome mode. This page paints
   its own topbar through that band and marks its controls no-drag, so v3
   (paint-through) is its real shape - and the hint is not drawn there.

Also: a turn's last assistant row can land after the host flips status to idle,
so the widget now listens for the host's session:turnEnded broadcast and does two
catch-up reads. And the preview tool referenced a Node-side constant from inside
the page stub, which made the project chip render its empty state - the same
preview-is-wrong-not-the-code trap as the missing vendor bundle.
